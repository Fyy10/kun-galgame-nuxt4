# 04 · 并行轨协议

> 2026-09-22 立。W1–W4 是一波一波串着走的，按那个节奏走完剩下的 319 条旧路由要两三个月。本文定并行的规矩。
>
> **同日晚改制**：五条车道压成「一个域一个独立会话」，各自在自己的 worktree 里从普查做到 PR。**操作手册是 [05-session-sop.md](05-session-sop.md)**，本文留下的是为什么这么并行、以及共享面清单——那两件事没变。

## 1. 瓶颈不是执行者

开几条轨不决定速度。决定速度的是两件事：

- **共享面**：每条轨都要改的那几个文件，是 N 条轨同时炸的地方；
- **验收**：读 diff、跑门、跑库、变异，都在督查一个人手里，天然串行。

所以并行的做法是「把共享面在扇出之前一次性占掉」，外加「把验收里可机械化的部分也派出去」。

## 2. 五条车道

| 车道 | 谁 | 并行度 | 产物 |
|---|---|---|---|
| A 普查 | 子代理，只读 | 6 | 每域一份报告：逐端点的字段、错误、权限、可见性、调用方、命名问题、疑似 bug |
| B 裁决 + 契约 | 督查，串行 | 1 | 契约提交：类型、错误码、i18n、迁移号、`app.go` 字段、路由注册位 |
| C 实现 + 测试 | 子代理，独立 worktree + 独立临时库 | 4 | 可合并的分支，九条闸全绿，变异全杀 |
| D 对抗复查 + 变异执行 | 子代理 | 每轨 1 | 复查报告 + 变异存活清单 |
| E 合并 / 浏览器 / 上线 | 督查 | 1 | master、实测、部署 |

**A 必须领先 B 两三个域**，否则 B 空等，整条流水线退化成串行。

## 3. 一条轨能碰什么

轨只写**自己域的新文件**：`internal/<domain>/apiv1/*`、`internal/<domain>/repository/v1_*.go`、`internal/app/v1_<domain>_*_test.go`、自己域的网页目录。

**绝不碰**（碰了就是 N 路冲突，全部由 B 在契约提交里先占好）：

- `internal/apiv1/**` 的表示层与 `collect` 游标机制 —— 它是所有域的地基，要改停下来问；
- `docs/{oauth,image_service,artifact}/`（infra 镜像，本仓任何人都不改）。

改制后自己加、但要守规矩的两处：

- **错误码**：`pkg/problem/registry.go`（常量 + `Codes`）、`registry_test.go`（`requiredCodes`，精确计数）、`apps/web/i18n/locales/zh-CN/problem.json`，**三处一译缺一不可**。两条轨同时加会冲突，**冲突一律两边都留**。
- **`internal/app/app.go` 的字段、`router.go` 的挂载点**：只加自己那一行，不重排别人的。

## 4. 预分配

- **迁移号**：扇出前按轨分配号段，写进任务书。W3 与 W4 撞过 098，就是因为两条轨同时挑号。
- **错误码**：契约提交里一次加齐，连 `zh-CN` 译文一起。
- **`app.go` 字段**：契约提交里先声明，轨只填。
- **金文件**（`testdata/routes.golden`、`legacy_route_baseline`）：是生成物。冲突一律**重新生成**解决，永远不要手工合并。

## 5. 九条测试闸

一条轨交付前自己跑完，缺一条不算完成：

1. `GOTOOLCHAIN=go1.26.1 make lint` + `go vet` 零输出（系统 Go 1.27 会让 errcheck 假失败）；
2. 契约门 G2–G17 / F1–F10；
3. spec 一致性：测试里每个响应都拿生成的 OpenAPI schema 校验；
4. **自己的**临时库，`-count=1 -p 1`，且 `KUN_REQUIRE_TEST_DB=1`——不设它，没 DSN 会静默跳过、假装通过；
5. 分页全量遍历：小 `limit` 翻完所有页，与直接 SQL 排序逐条相等，无重复无遗漏，**并且数据里要有并列的排序键**（见 §7）；
6. 先于实现提交的变异清单，每条都要能让某个测试变红；
7. 每个声明的错误码至少一个用例；
8. 网页：**`pnpm typecheck`**（不是 `pnpm vue-tsc --noEmit`，见下）+ eslint + vitest，外加**真的 SSR 渲染一遍改过的页面**（类型检查永远不解析模板里的组件）；

   > **`pnpm vue-tsc --noEmit` 在本仓库什么都不检查。** `apps/web/tsconfig.json` 是 `{"references": […], "files": []}`，不带 `-b` 就是编译一个空程序，永远 exit 0。实测：往 `Like.vue` 里塞一句 `const x: number = "not a number"`，它照样 exit 0，而 `pnpm typecheck`（`vue-tsc -b --force`）当场报错。W5a 之前的几波「typecheck 通过」都是这么来的，包括督查自己跑的。
9. 浏览器实测——改制后是会话自己的活，没有替代品。

## 6. 变异清单先于实现

题目 8–12 条，每条是一行语义改动。原本由督查在**派发之前**写进任务书——执行者不能给自己出题，否则测的是它自己的理解，不是契约。

改制后一个会话既是执行者又是督查，**唯一的替代品是顺序**：变异题必须**先提交到分支上**，再写实现，由 git 历史作证。事后补的不算数。

一条变异如果**编译不过**，它不是变异，是无效题，要换一种等价的破坏方式（例：删掉跳过封禁用户的 `if` 会让 `authors` 变成未使用；改成恒假才是有效题）。

## 7. 今天学到的两条（2026-09-22，W4 验收）

- **执行者没有数据库，它写的测试就只是草稿**。`topic_favorite.updated` 与 `topic_upvote.updated` 是 `NOT NULL` 且无默认值，v1 的 raw INSERT 不写它们，收藏和推**每一次都 500**。执行者在报告里写出了这个风险，但证实不了；第一次真跑就是 6 条红。所以车道 C 的代理必须自带临时库。
- **排序测试的数据里必须有并列**。种子给每个用户一个各不相同的秒，于是把键集的 `id` 决胜键整个删掉，三个分页测试照样全绿。加了三条共享同一时刻、跨页边界的行才测到。

## 8. 合并：走 PR

2026-09-22 之前是「验收一条直接落一条 master」。改成 PR，原因是会话之间互相看不见：

- 分支推上去就是**认领**，`git ls-remote` 是唯一一张不会过期的认领表；
- PR 上自动跑 `unit` / `db` / `web` 三个作业，是九条闸里 1、3、4、8 的**机械复核**——会话自己跑过一遍，CI 再跑一遍，两边都绿才有意义；
- 变异清单、普查结论、闸的勾选留在 PR 正文里，是这一波唯一的对外证据；
- 冲突在 PR 上两两解决，不会攒到最后 N 路一起炸。

规矩：

- **一个域一个 PR**，squash 合并，master 保持线性。
- **合并即上线**（master 一推就构建部署，`build-and-push` 没有路径过滤，纯文档 PR 也会重新部署）。所以**一次只合一个**，合之前 `gh pr list` + `gh run list --branch master` 确认上一次部署完成——master 的构建 concurrency 是 cancel-in-progress，连着合会取消前一个。
- **合完自己盯部署**，Dokploy webhook 回 2xx 不代表真的部署了。
- 后合的 PR rebase 到 master，不 merge commit。
- 金文件（`routes.golden`、`legacy_route_baseline`）冲突一律**重新生成**。

「全部跑完最后一起合」仍然不用：N 路冲突集中在同一时刻，而且合并之前没有任何证据证明它们放在一起是对的。真需要「一起上线」的原子性时，用 release 分支 `v1-<批次>`，各 PR 合进去，在上面跑一次全量，再一把合 master。
