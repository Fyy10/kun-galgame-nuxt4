## 转换器验收

- **范围**：落在可写路径内，没碰契约文件。它自己的六个变异都真实有效，并主动报出两个问题：
  - `atom.Lookup` 连属性名也认；
  - 不变量检查分不出「意外的空段落」。
- **语料差分**：18327 份生产正文全部转换成功，并全部通过提交的 schema。可见文本与旧 HTML 管线一致，只有 9 份按裁决有差异：
  - 5 份非元素尖括号词；
  - 3 份 `kv:`；
  - 1 份不可用图片的 `alt`。
- **验收修掉两个 bug**。它们都是差分测试「去掉全部空白再比」看不到的：
  - `*word*` 换行 `next` 变成 `wordnext`：软换行落在行内容器之后时，找邻居只看同级，没有往上走。修成沿行内祖先找左右邻字符；图片这类非文字邻居补空格，`<br>` 视为行界。
  - 用户写的 `<src>`、`<id>` 被当成标签吞掉：`atom.Lookup` 也收录属性名。换成显式的 HTML 元素表（WHATWG 索引加旧帖用到的过时元素）。
- **补的测试**：新增「保留词边界」的语料比较，只对 R14 有意删除的 CJK 两侧空格放行。验收时它在生产语料上没找到上面那个 bug 的实例（本站软换行两侧几乎都是中文），所以两个 bug 都靠新增的精确 JSON 用例钉住。另补 `javascript:`、`data:`、无主机 `http:` 链接与 HTML `<img>` 长 `alt` 用例，此前没有任何测试覆盖。
- **变异**：验收的 15 个变异里，最初 3 个存活（`javascript:` 放行、无主机 http 放行、HTML 图片 alt 不截断），补用例后全部被杀。唯一的等价变异是去掉 scheme 小写化，因为 `url.Parse` 已经小写。
- **性能**：整份语料转换 181 毫秒，旧 HTML 管线 341 毫秒。P99 130 微秒，最大的正文（200 KB）2.6 毫秒。
- **其余门**：模糊测试 60 秒无失败；lint、全部测试、spec 无变化；一次性库上 DB 全量套件绿。

## 渲染器验收

- **报告**：如实，列了 18 条疑点，其中两条是「灯箱打开的是变体图」与「@ 点击跳 `/user/:id` 而 href 是 `/user/:id/info`」，都与现行行为一致。
- **验收修的**：
  - 松散列表里任务项的复选框在 `<p>` 外，自成一行；改为放进首段，与 goldmark 一致；
  - 紧凑列表里的空段落什么都不出；改为保留空行；
  - 标题层级夹到 2–6；
  - 非法 TeX 的用例只断言「不抛错」，改为断言 KaTeX 的错误标记与源文；
  - 补 `compact` / `className`、`mailto` 与大写 scheme、不安全视频地址、非数字 `reply_id` 用例。
- **变异**：10 个变异全部被杀。

## 端到端交叉验证

用 Go 把 18327 份语料转成 JSON，逐份交给网页的 `ContentNodes` 做 SSR，再抽文本与文档文本比较。结果：

- 0 份抛错；
- 忽略空白与 BOM 后 0 份不同；
- 空白敏感比较有 14 份不同，全部来自测试脚本自己在 TS 里近似的东亚宽度判定（emoji、小型标点）与 Go 的宽度表不一致，不是渲染器的问题。

## 留下的

- KunUI 的灯箱读 `<img>` 的 `src`，贴纸（`_320` 变体）打开的是小图，与现行一致。要看原图需要 KunUI 支持 `data-full-src` 一类的属性，已告知用户，未改 KunUI。
- `repr.Image.url` 的上限是 512，正文 `url` 是 2048。CDN 地址很短，暂不统一。
